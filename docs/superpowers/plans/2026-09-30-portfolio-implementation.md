# Portfolio Implementation Plan

> Актуализация 1 октября 2026: пользователь утвердил в чате полное переоформление «Графитовый рельеф». Оно заменяет нижеописанные цветную палитру и Canvas-сцену интерактивной DOM-типографикой, не меняя схему данных, контроллер языка или способ размещения. Locale-переход заменён на 860 мс сборку букв с общей геометрией RU/EN. Задачи 1–4 и локальная часть задачи 5 выполнены; публикация и живая проверка продолжаются. Нижний план сохраняет первоначально согласованный порядок работ.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать и опубликовать двуязычное портфолио fraeer995-ux с интерактивной поверхностью из символов и простым добавлением проектов.

**Architecture:** Статическая страница, CSS и ES-модули. Отдельные модули отвечают за тексты и язык, предпочтения, данные проектов, Canvas и эффекты указателя. GitHub Pages публикует main из корня репозитория без сборки.

**Tech Stack:** HTML, CSS, JavaScript, Canvas 2D, Node.js для локального сервера и встроенных node:test; CUA для проверки браузером; подключение GitHub и доступный браузер Edge для публикации. Новые npm-зависимости не требуются.

**Spec:** `docs/superpowers/specs/2026-09-30-portfolio-design.md` — утверждено пользователем 30 сентября 2026 года.

## Global Constraints

- Бренд — `fraeer995-ux`; специализация: Telegram-боты и мини-аппы, сайты и лендинги, парсеры маркетплейсов.
- Публичный репозиторий и адрес: `fraeer995-ux/fraeer995-ux.github.io`, `https://fraeer995-ux.github.io/`.
- Статический сайт без серверной части, платных сервисов и обязательного сборщика.
- Данные автора и проектов находятся в одном файле `content/portfolio.json`; исходный массив проектов пустой.
- Первый запуск открывается на русском; язык и тема сохраняются в localStorage, ошибка хранилища не ломает сайт.
- Все тексты интерфейса и метаданные переводятся; html.lang, title и объявления для скринридера обновляются согласованно.
- Переключение языка длится около 860 мс: хаотическая сборка букв с отменой и общей геометрией RU/EN.
- При уменьшении движения отключены непрерывное движение, пружины, наклоны, магнитное смещение и анимированные переходы.
- Canvas прекращает цикл на скрытой вкладке и вне экрана; pixel ratio ограничен 2; вертикальная прокрутка на телефоне не перехватывается.
- Email из аккаунта не публиковать. Контакт GitHub; Telegram появляется только при заполненном настоящем адресе.
- Не публиковать образцы проектов, выдуманные достижения, служебные файлы и токены. Поиск, аналитика, админка и демонстрации услуг не входят в первую версию.

## Review Focus

1. Быстрые повторные нажатия RU/EN во время перехода: окончательное состояние соответствует последнему выбору, нет смешанной локали.
2. localStorage выбрасывает исключение или хранит неизвестные значения: страница остаётся рабочей с допустимыми настройками.
3. Некорректный JSON, вредоносная ссылка, отсутствующий перевод или повторный id: корректные проекты продолжают отображаться, небезопасная ссылка не появляется.
4. Телефон, уменьшение движения, скрытая вкладка и изменение размеров: можно прокручивать страницу, нет лишнего цикла Canvas и горизонтального переполнения.
5. Новое имя проекта или длинный английский текст: карточка и шапка сохраняют читаемость, фокус и ссылки работают.

## Task 3: RU/EN, предпочтения и плавный переход

**Правка пользователя после реализации:** вместо blur/сдвига использовать хаотическую сборку букв за 860 мс. `text-transition.js` создаёт общую область по размерам обоих переводов и декоративный слой букв с отменой; outgoing-фаза теперь мгновенная, incoming вызывает этот слой. Проверки включают неизменную геометрию RU/EN, завершение букв и быстрые повторные клики. Это заменяет первоначальные параметры 180/240 мс и blur ниже.

**Files:** Create `assets/scripts/copy.js`, `assets/scripts/preferences.js`, `assets/scripts/language.js`, `tests/copy.test.mjs`, `tests/preferences.test.mjs`, `tests/language.test.mjs`; modify `assets/scripts/main.js`, `index.html`, `assets/styles/motion.css`.

**Interfaces:**
- `copy` содержит одинаковые ключи для ru и en: навигация, главный экран, направления, проекты и фильтры, контакт, подсказки сцены, пустые состояния, ошибки, метаданные и доступные названия контролов. `translate(language,key):string` возвращает текст ключа с fallback на ru.
- `readPreferences(storage)` возвращает `{language:'ru'|'en',theme:'dark'|'light'}`; ключи `portfolio.language` и `portfolio.theme`; исходные значения ru/dark. `savePreference(storage,key,value)` перехватывает ошибки записи.
- `applyLanguage(document,language)` обновляет отмеченные элементы, атрибуты, html.lang и метаданные; изменение динамических проектов выполняется через `setLanguage` из задачи 2.
- `createLanguageController({initialLanguage,commit,animatePhase,persist,reducedMotion})` возвращает `{request(language):Promise<boolean>,getLanguage():string}`. `animatePhase(phase:'out'|'in',signal:AbortSignal)` обеспечивает 180/240 мс и отмену. `commit(language)` атомарно обновляет статический DOM и проекты; true означает завершённый переход, false — отменённый новым запросом. Последний запрос побеждает; устаревший не вызывает commit/persist после отмены.

## Execution Handoff

Рекомендуется Native: основной агент реализует задачи в этой сессии, затем отдельный агент проверяет весь результат. Для небольшого статического сайта это позволяет сохранить цельную визуальную композицию и проверить данные, языки и публикацию вместе. Альтернатива Subagent-driven: отдельный исполнитель и ревьюер для каждой задачи, затем итоговый обзор; больше обменов контекстом.

Реализация начинается после проверки этого плана пользователем и выбора способа исполнения. Native требует `superpowers:executing-plans`; Subagent-driven требует `superpowers:subagent-driven-development`.
